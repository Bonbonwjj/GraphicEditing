# 绘图平台实施状态

更新时间：2026-10-10。本文说明本地代码实际实现，不把目标设计或模拟模型测试当作真实模型效果证明。

## 已接入的流程

| 部分 | 当前实现 |
| --- | --- |
| Chat Skill | `chat_agent.py` 每轮加载 `skills/chart-chat-edit/SKILL.md`；核对原话、目标、父版本、结构化意图、允许路径和数据列引用。 |
| 会话与候选 | `chat_harness.py` 在 `.chat/` 保存身份、原话、轮次、候选代码和图片；下一轮使用活跃成功候选，失败不覆盖它，可选择旧成功候选继续。 |
| 用户应用 | 新图先显示在 Chat；明确应用指定候选后才更新中央图和正式代码；应用前检查代码、数据、共用依赖和平台规则指纹，保存失败尝试回滚本次触及文件。 |
| 规范化 | 所选 Skill、样式和相关代码进入规范化 Agent；与 Chat 共用候选出图和应用流程，原自动保存行为已取消。 |
| 参照 A 改 B | A 作为只读上下文和固定版本图片，B 为独立目标；缺少可唯一定位的参照时允许补上下文并重试。目标不会从用户文字中自动切换。 |
| 批量 | 逐图调用、保存候选、报告成功或失败，可逐图应用；某张失败保留其他结果。 |
| 文件边界 | 候选输入采用只读项目副本；当前 Harness 写入范围只开放选中图的入口脚本。独立适配模块新增流程尚未开放，需在入口内安全隔离或报告无法完成。 |
| 布局冲突 | 真实尺寸下检查文字相交、裁切及可识别对象冲突；Chat 最多一次自动修复。仍冲突则展示诊断图；用户明确接受已显示冲突时记录例外，并绑定布局签名及正式版本。 |
| 数据检查 | 比较实际绘图对象的数据签名、可见性和轴范围；箱线/小提琴优先用已有统计和数值方向检查，宽度变化单独作为样式变化。新增元素、未知对象和复杂语义仍需审阅。 |
| 清理 | “完成并清理”保留当前代码和图片，删除该图正式历史与 Chat 候选，关闭相关会话；不会清除已有 Git 提交。 |
| API 配置 | 顶部“⚙ API 配置”填写地址、模型和密钥；工作台将当前设置传给本进程或两个独立 Agent。密钥存入 macOS 钥匙串，仅地址和模型写入 Git 忽略的本地设置文件。可测试连接或清除配置，无需重启。 |

页面图名继续使用 `X轴组别1&X轴组别2&……_Y轴标题`。后台稳定身份与名称分开；现有文件名路由仍保留，`.chat/identity.json` 为项目和现有图入口登记稳定 ID。直接重命名入口文件的身份迁移和一个脚本输出多个逻辑图，仍不属于本轮已完成能力。

## 运行方式

默认启动 `server.py`（8765），规范化和 Chat Agent 在同进程运行。可设置 `NORMALIZER_AGENT_URL=http://127.0.0.1:8766`、`CHAT_AGENT_URL=http://127.0.0.1:8767` 使用独立服务。三个角色使用相同输入/输出职责，不靠 Agent 直接写正式文件。

模型服务现在优先通过页面配置；环境变量 `OPENAI_API_KEY`、`LLM_API_URL`、`LLM_MODEL` 继续作为兼容方式。模型服务商由所填 API 地址决定。测试连接只发送固定短句；实际改图请求会发送完整的已整理绘图 CSV、相关代码、最近轮次和当前候选，而非仅发前三行；当前上下文总大小限制为 8 MB，超过时明确报告。项目各 `data/` 与 `lib/` 文件目前保守纳入上下文/指纹，尚未实现精确最小依赖分析。

默认使用文本上下文。`CHAT_MODEL_VISION=1` 时向支持图像的模型加入可用的目标/父候选和参照图；上下文标明图片顺序与目标图片是否可用，不能把只有参照图误写成已经看过目标图。供应商密钥不进入候选运行环境。

实际候选执行依赖 macOS Seatbelt。候选可读受控副本及必要 Python/字体运行库，输出只写临时运行目录，网络和新进程被限制，超时明确终止。若操作系统或外层沙箱不允许启动隔离器，则拒绝运行候选，没有无隔离后备路径。

## 当前接口

前缀为 `/api/projects/{project}/chat/sessions`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET` 前缀（可带 `?charts=a,b`） | 列出匹配目标集合的会话 |
| `POST` 前缀 | 根据 `charts` 和可选 `reference_charts` 创建会话 |
| `GET /{session_id}` | 读取轮次、候选和状态 |
| `POST /{session_id}/turns` | 发送 `user_message`，可指定父候选、参照、已披露布局例外 |
| `POST /{session_id}/normalize` | 以 `skill_id` 生成规范化候选 |
| `GET /{session_id}/drafts/{draft_id}/image` | 读取已经保存的候选图片 |
| `POST /{session_id}/drafts/{draft_id}/activate` | 从指定成功候选继续 |
| `POST /{session_id}/drafts/{draft_id}/apply` | 复核基准后应用该版 |
| `POST /{session_id}/drafts/{draft_id}/discard` | 放弃尚未应用的候选 |

规范化 Agent 独立服务使用 `POST /v1/normalize`，Chat Agent 使用 `POST /v1/chat-edit`。页面中的项目文件名用于路由，Agent 请求包含稳定图 ID；响应必须原样回传轮次及身份字段。

模型设置接口为 `GET/POST/DELETE /api/model-config` 及 `POST /api/model-config/test`。读取接口只返回地址、模型、配置状态和存储位置，不返回密钥。保存请求只接受当前工作台来源的 JSON；在工作台运行的 macOS 环境中使用系统钥匙串。

会话状态主要为 `open`、`running`、`interrupted`、`closed`；候选状态包括 `rendering`、`preview_ready`、`needs_clarification`、`render_failed`、`validation_failed`、`revision_conflict`、`applied`、`discarded`。Agent 四种业务结果保持 `candidate`、`needs_context`、`needs_clarification`、`cannot_complete`。设计契约中的部分细分阶段目前在单次请求内部顺序执行，并非每个阶段都有独立持久化事件或实时推送。

## 规范化收尾

样式包现为 1.1：已整理数据可明确提供误差列或汇总换算依据，无默认 SEM；原图缺少模型时不自动拟合；热图色带保持；12 pt 定义为 x 轴整组下移，y 轴与图不移动；小提琴 25%/75% 横线各为中位线一半。英文重字重缺失时使用已配置字体回退并记录，中文重字重无法满足时报告未验证。

辅助函数实现不等于所有任意 artist 自动规范化。Agent 仍需识别图种和可修改对象，Harness 无法验证的规则必须在候选报告中保留。详见 [规范化验收记录](acceptance/README.zh-CN.md)。

## 尚未被本次验证覆盖的部分

- **真实部署模型**：页面配置入口已可用；当前仍没有实际 LLM 密钥，尚未验证所选供应商/模型对真实用户图、多轮语言与结构化输出的稳定性；用户在页面保存密钥后需要真实模型联调。
- **全面语义和视觉保证**：代码/对象检查不证明没有歪曲用户意思，也不能完整识别复杂自定义 artist、所有背景同色遮挡或任意非预期重叠；模型自查与用户审阅仍有职责。
- **全站隔离**：只有新 Chat/规范化候选路径接入新隔离器；已有上传转换、历史预览和手动代码修改仍存在旧 renderer，不可宣称所有上传 Python 已安全隔离。
- **多人线上服务**：目前没有登录、用户/项目权限、请求鉴权、跨进程事务锁或分布式队列。当前锁是单个 Python 进程内的协调，并非生产多用户并发保障。
- **更广的运行支持**：暂不提供 Linux/Windows 候选沙箱实现；其他平台明确报告不可执行，不自动降级。
- **持续验收**：新增图种、复杂多面板、真实数据模板和长对话仍需要持续回归；不能把本轮有限样本外推为所有图都已验收完成。
