# 通用工程改图流程优化

## 本次问题

foraging 的“将图的轴加粗”请求在模型响应的数据引用校验阶段失败，错误为 `Data reference is not in the read-only snapshot`，尚未开始候选渲染。会话快照包含 35 份 CSV 的有界样本、原分析源码和适配入口。旧流程要求外观修改也列出实际 CSV 引用，但原工程路径、只读快照路径和临时运行路径属于不同命名空间，模型一旦混用路径或返回错误哈希便直接结束本轮。

历史会话没有保存被拒绝的模型原始响应，因此不能断言当时究竟是哪一个路径或哈希有误。本次同时处理路径身份、外观请求过量上下文和校验错误修复三个方面。

## 新流程

1. 识别当前入口类型及请求。轴线、字体、颜色等外观请求优先操作适配器中的 `customize(figure)`。筛选、统计、分布和图型转换继续走源码及数据结构读取流程。
2. 外观适配流程向模型提供当前可写入口、必要目标/面板信息及已有上下文，省略原分析正文和原始数据内容。明确返回 `data_access: preserve_existing`、`read_data_refs: []`，保持继承的本地数据读取逻辑。
3. 主程序比较新旧 AST：除 `customize` 函数体外必须相同；其中已有的导入和非样式调用也必须保持。修改入口、补丁字典、读文件调用等不能使用上述例外。候选仍需接受原有原图/候选渲染、数据、字体、可见范围及布局检查。
4. 正常数据引用使用完整 `plot_data.path`。主程序还允许注册表明确指定的源码根相对路径，但必须精确映射到唯一快照文件。禁止猜测 basename、跨目录搜索、临时绝对路径或目录穿越。不替换模型给出的错误哈希。
5. 数据路径/哈希/列名不一致进入现有模型纠错机制，与其他修复共享本轮最多三次调用；不无限重试。需要补读源码时恢复数据 schema，并按真实源码范围继续。

注册表本身不作为 Python 源码发送给模型。Harness 从本轮注册表生成 `data_reference_roots` 元数据，供路径校验使用，避免把整份注册表加入提示词。

Skill 入口是 `skills/chart-chat-edit/SKILL.md`。应用的 `chat_agent.skill_guidance` 显式加载适用的 adapters、appearance、large-data 参考文件；快速协议由应用补充。仅修改 Skill 文本不会改变硬性校验，必须同步维护实际工作流程。

## 验证与边界

- 9 项新增回归涵盖轴加粗、外观请求缩减、混合科学请求、入口/读者保护、路径别名、哈希/列名拒绝、有限纠错、无注册表正文时的元数据路径和既有导入保持。
- 回放真实失败会话，使用固定模型响应测试传输及校验，不调用外部模型：文字上下文从约 63,035 字符缩减到约 2,002 字符，均不计图片和系统指令。不能把字符下降直接换算为端到端耗时下降。
- 用 foraging 完整本地数据在临时快照中运行原图与轴加粗候选，约 61.13 秒；候选 PNG 生成，科学数据对比为 `unchanged`。布局检查仍为 `conflict`；没有跳过布局检查、自动接受冲突或应用候选。
- 原分析计算尚未分离为独立绘图数据包，所以本地渲染仍需约一分钟。本次没有实现拆图阶段的入口级批量捕获或承诺固定提速倍数。
