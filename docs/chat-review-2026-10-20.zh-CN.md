# 改图检查核查与参数路径试验

日期：2026-10-20。基于 v0.1.1 本地源码；本页的新增实现尚未重新打包或上传 GitHub。

本文保留首轮核查和试验记录。后续完成的参数适配、转换扩展、共享模块衔接及当前架构，以 [对话改图 Harness 与本轮优化说明](CHAT_HARNESS.zh-CN.md) 为准。

## 已查到的历史原因

只读检查本机工作区留存的会话，共找到 19 条轮次结果：待审阅候选 5、图片变化未达要求 1、无法完成 8、检查未通过 2、需要确认 2、已满足要求 1。记录包含旧代码运行结果，没有按每次运行的源码版本分组，不能据此计算当前版本成功率。

两条严格标记为 validation_failed 的原因为：

- “把这2个图改为小提琴图”：转换报告为 unverified，实际捕获样本次数为 0，普通数据比较为 unchanged。这里没有证据表明数据被改，直接原因是缺少目标图型的样本核对证据。
- “将我选中的2个图改为箱线图”：没有专门转换报告，普通比较记录 5 个线条变化、4 个误差线/散点对象移除、8 个对象新增（包含分布统计元素）。这符合图型转换会改变图元的情况，但当时落入普通图元比较而被拦截；记录没有完整样本捕获，不能进一步证明转换前后的原始样本等价，也不能据此断言原始 CSV 被改。

其他结果包含：模型接口连接失败、429 限流、旧响应格式要求、未解决的修改意图、数据列引用不匹配、批量指令被误解为缺少第二张目标图，以及导出图片逐像素相同。部分问题已有 v0.1.1 修复，历史错误记录不会因此自动改成成功。

## 当前决定如何产生

候选运行完成后，按顺序检查：标准化结构、图型转换、绘图数据/映射、显示范围或可见性授权、新增元素授权、字体、布局、坐标轴要求、图像实际变化。先遇到的阻断条件决定当前状态，不能把首个原因当作全部检查都已完成的证明。

新增诊断将图型转换“无法核对”与“核对不一致”、普通绘图数据/映射差异、布局、字体、轴要求和运行错误区分展示，并提供具体原因、处理建议及可用的变化对象编号。只改变解释，不将无法核对自动算作通过。旧候选也能通过公开响应获得诊断；旧记录无法补回当时未保存的自动修复过程。

新轮次保存每次实际出图的状态及诊断，避免只看到自动修复后的最终原因。模型连接、格式等尚未出图的失败仍通过轮次错误说明展示，不伪装为出图检查记录。

## 各类图的数据检查边界

| 图或元素 | 当前可核对的内容 | 仍需核查的内容 |
| --- | --- | --- |
| 折线 | 实际 X/Y 数据完整数组的签名 | 系列科学含义、标注与数据的对应、复杂变换 |
| 散点 | 点坐标；本次增加颜色所映射的数值数组 | 点大小对应的变量、类别调色映射、遮挡 |
| 竖向柱状图 | 柱中心、起点、柱高 | 汇总是否应为均值/中位数、误差定义、原始样本来源 |
| 横向柱状图 | 本次按方向核对柱起点、柱宽与组位置，柱厚度保持为样式 | 分组/堆积对应、源数据汇总规则 |
| 热图 | 单元数值；图像 extent；本次增加 QuadMesh 网格坐标 | 行列标签对应、颜色归一化/范围的含义 |
| 误差线 | 已绘制误差线段、容器角色及数据系列 | 是否应为 SD/SEM/CI，计算依据是否正确 |
| 箱线/小提琴 | 捕获的输入样本和统计对象；支持范围内与 CSV 全分组逐值匹配 | 多子图、不同数据源、横向转换、附加散点及重排组别等尚无完整转换核对 |
| 直方图 | 生成的柱几何能参与比较 | 分箱边界、密度/计数定义及原始样本的跨图型对应 |
| 自定义 artist/复杂变换 | 部分几何与可见性，无法识别的对象有覆盖限制 | 不能承诺数值等价或科学含义不变 |

本次具体补了三个缺口：横向柱宽作为数值比较、散点颜色数值数组比较、QuadMesh 网格坐标比较。它们不构成所有图型转换都已正确的证明。

后续应给图建立可复用的数据说明：原始数据路径、样本列、分组列、筛选条件、缺失值策略、聚合/误差定义、单位，以及子图和系列的稳定身份。转换时比较这一层的数据与映射，再分别验证目标图型；避免强行比较转换前后的图元形状。未经确认的规则不能静默决定科研数据处理方式。

## 参数快速路径（首版试验）

以下简单句式可尝试直接修改已有明确参数：

- X轴标题字号改为12
- Y轴标签字号改为14
- 折线颜色改为红色（或六位十六进制颜色）
- 图例位置改为左上角
- X轴范围改为0到4

首版只支持可静态定位的单 Axes、直线执行脚本，以及已有的字面量 fontsize/color/loc 或 set_xlim/set_ylim 参数。需要已有明确目标，不猜测多条线、多个坐标轴、动态变量、分支/循环或共享函数的行为。范围修改不隐含设置端点刻度。超出支持范围时走原 Agent；命中后仍走真实出图、数据/布局检查、候选审阅与应用流程。

命中并通过检查的候选不调用模型。若候选检查有问题，原自动修复仍可能调用模型，总调用次数继续受每图每轮三次约束。当前仍有上下文准备和本机出图开销，没有宣称端到端耗时已经降低多少。

## 共享模块与单图影响

本次参数路径只修改选中图的入口文件，不编辑共享模块。实际测试包含第二张图及共享文件，应用后均保持不变。

共享函数修改仍可能影响全部调用图，不能仅凭“展示影响范围”保证其他图不变。后续自动衔接应先尝试入口已有参数；没有参数时优先设计单图配置或入口适配，维持其他调用默认行为；确需共用修改时进入共享模块候选，展示受影响图并验证。当前尚未实现 Chat 到共享模块候选的自动路由。

文件不变与图像不变也不等价：如果改了其他图依赖的共享文件，需重新出图核对；即使仅选中一张图进行代表验证，也不能宣称其余图已验证。


## 本次验证结果

- 参数路径、诊断、Harness、精简响应相关 55 项测试通过（75.194 秒）。参数路径含四类真实出图、零模型调用、应用只修改选中入口，以及重复范围请求不调用模型的检查。
- 绘图检查与转换相关 33 项测试中 31 项通过、2 项跳过（139.575 秒）；两项跳过均因 local 模式没有 OS 文件系统沙箱。横向柱宽、散点颜色值、热图网格的新用例通过。
- 真实 Harness 与真实 Python 出图的 9 项集成测试全部通过（366.302 秒），覆盖多轮/应用、批量独立结果、依赖冲突、数据改变阻止应用、布局修复/例外、箱线图继续修改及标准化。模型响应使用模拟数据，没有验证真实服务商效果。
- 合计 97 项 Python 测试：95 项通过，2 项按运行模式跳过；Node 前端状态/候选显示检查通过，包含诊断、检查过程及 HTML 转义。
- 未重新打包、上传或重启个人常用工作台；所有真实运行测试使用独立临时项目。
