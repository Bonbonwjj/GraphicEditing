# Chat 改图 Skill 行为验证记录

日期：2026-10-03。范围：验证与修订 `skills/chart-chat-edit/SKILL.md`，未接入生产 Chat 接口，未修改正式项目图、CSV 或共用绘图函数。

## 方法与结果

由本会话的两个独立 Agent 加载 Skill，处理隔离的合成请求，保存真实 JSON 回复。Agent 未得到期望答案，也未读取检查脚本或报告；同一 Agent 处理多个案例，因此不是互相完全隔离的统计实验。没有调用平台配置的外部模型 API；该终端没有配置 API 密钥。

随后审阅候选源代码，在临时项目内实际渲染，比较 Matplotlib 绘图对象中的数据、样式和位置，计算文字边界相交及裁切，并查看输出 PNG。检查脚本仅用于本次已审阅样例，不是运行任意上传代码的安全沙箱，也不是通用布局检测实现。

| 案例 | 用户要求或情况 | 实际行为与结果 |
| --- | --- | --- |
| 01 | Obs 线宽 2.5，图例图外右上，其他不变 | 仅本图入口设置 Obs 线宽；保留已正确的图例位置。成功渲染，数据和 Control 保持不变。 |
| 02 | 图例再左移一点，保留上一轮修改 | 基于父候选，把 anchor x 从 1.02 改为 1.00；保留 Obs 线宽 2.5。实际图例左移，垂直位置不变。 |
| 03 | 两条线中未指明“这条线” | 请求确认 Obs 或 Control，没有候选文件。 |
| 04 | 参照 A 的 Obs 颜色改 B | 只将 B 的 Obs 颜色改为 #006644；不写 A、数据或共用函数。成功渲染。 |

第二轮 10 个案例均符合本次检查的行为预期；3 个常规修改候选（01、02、04）通过本次数据、样式与布局检查。09 是故意制造冲突的诊断图，不能把“按要求生成”误写成“布局通过”。实际渲染了 4 个候选及各自基准图。

## 发现与修订

第一轮候选回复正确列出了数据文件，但没有逐列给出实际使用的 CSV 字段。补充 Skill，明确 `read_data_refs` 每项必须包含文件路径、SHA-256，以及带 `name`、`role` 的非空 `columns` 列表，包括共用函数实际使用的列。

重新生成 01、02、04、09 后，均明确记录 `group`、`x`、`mean`；没有把存在但未使用的 `sem` 宣称为已绘图输入。第一轮回复及检查结果保留于 `initial-responses/` 和 `initial-results.json`。

Skill 格式校验 `quick_validate.py` 已通过。格式校验不代表行为可靠性证明。

## 可复查产物

- `inputs/`：10 个完整请求，包括用户原话、版本 ID、代码、数据、参照和 Harness 反馈。
- `responses/`：实际最终 Agent 输出；`initial-responses/` 为修订前输出。
- `artifacts/`：实际渲染的父版本、候选 PNG 和绘图对象状态。
- `results.json`：第二轮逐项结果，`errors` 为空表示未发现本脚本覆盖的问题。
- `manifest.json`：最终 Skill 与输入输出文件的哈希。
- `evaluate.py`：对保存的回复重新执行检查，不重新调用模型。

复查命令（需安装 Matplotlib 与 Pandas）：

```bash
python docs/chat-acceptance/evaluate.py
```

## 实际边界

- 这是第一轮小规模合成案例验证，主要使用双系列折线图，不证明所有图种、复杂多子图和任意用户表达都可靠。
- 02 验证正确提供父候选时 Agent 能继承修改，不代表真实 UI 已实现会话、候选持久化或防串图。
- 08 使用提供的 Harness 冲突反馈，10 使用实际渲染产生的反馈；二者不代表 Agent 自己能够准确发现所有碰撞。
- 文字边界相交是保守检测，未覆盖所有数据遮挡、复杂图形、不同后端或导出格式。图像已另行查看，但不能宣称通用视觉验证完成。
- 平台当前配置的外部模型未参与本次验证，后续接入时仍需对部署模型和完整接口流程做联调。

结论：已完成 Chat Skill 的首次行为验证与一次针对性修订，可进入 Harness 接入；仍需在真实流程及更多图种中持续验收。
