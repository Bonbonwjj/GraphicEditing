# Plot Forge 图表工坊用户使用说明

适用版本：v0.1.3 · 更新日期：2026 年 10 月 21 日

Plot Forge 用于管理科研绘图项目，通过对话调整图表、批量统一样式，并将正式结果共享给团队。绘图在自己的电脑上执行；使用 AI 改图时，相关代码、绘图数据及按配置启用的图片会发送给你配置的模型服务。

## 1. 第一次使用

### 下载并打开 Mac 应用

1. 在 [v0.1.3 发布页面](https://github.com/Bonbonwjj/GraphicEditing/releases/tag/v0.1.3)下载 `Plot-Forge-v0.1.3-macOS-arm64.zip`。本次安装包适用于 M 系列芯片 Mac。
2. 完整解压，将 `Plot Forge.app` 拖入“应用程序”，然后双击打开。
3. 首次启动需要初始化内置运行环境，请稍等。随后应用会自动在浏览器中打开本地工作台，无需另行安装 Python、Git 或 Conda。
4. 后续使用直接打开 App。关闭网页后，本地后台可能仍在运行；再次打开 App 会复用已有后台。

当前 Mac 包尚未完成 Apple 公证。若被系统阻止，在确认来源是本项目发布页面后，可到“系统设置 → 隐私与安全性”查看是否提供“仍要打开”。如果系统提示文件已损坏或没有继续打开的选项，请记录完整提示并联系维护者。

请使用 App 实际打开的网页地址，端口可能随本机占用情况变化，不必固定输入某个端口。

### 配置模型 API

查看已有项目和图片不需要模型 API；AI 改图和需要模型参与的标准化操作需要先配置。

1. 点击右上角 **API 配置**。
2. 填写完整的 **Chat Completions 地址**、**模型名称**和个人 **API Key**。可点击“使用默认模型与地址”填入预设，但仍需填写自己的 Key。使用公司内网模型时，先连接相应网络或 VPN。
3. 根据服务端支持范围设置 **Chat 改图最大输出 token**。这个值是单次响应上限，并不代表每次一定消耗这么多；过小可能导致代码或返回内容被截断。
4. 如果模型支持图片输入，并希望它参考当前图或参照图，可勾选“改图时将当前图和参照图传给支持视觉的模型”。
5. 点击 **保存配置**，再点击 **测试已保存配置**。

测试成功表示简短请求可连通，不保证复杂改图一定成功。密钥优先保存在本机系统凭据库，页面不回显；系统存储不可用时可能仅在当前会话生效，重启后需要重新输入。已配置后留空 API Key 再保存，会保留原密钥。

## 2. 认识工作台

| 区域 | 用途 |
| --- | --- |
| 左侧“项目资源” | 切换项目、打开图表、导入代码和数据、管理标准化 Skill |
| 中间“图像预览” | 查看正式图集、选择一张或多张图、批量操作 |
| 中间“绘图代码 / CSV 数据” | 查看当前图的代码与数据，或手动修改代码 |
| 右侧“对话改图” | 输入需求、查看候选、继续修改、确认应用 |
| 右上角“团队协作” | 查看共享位置、设置协作者身份、发布正式修改 |

**候选图、正式图和团队版本是三个步骤：**右侧生成候选 → 点击“应用此版”更新本机正式图 → 在“团队协作”中发布，其他成员才能获取。

## 3. 打开或导入项目

### 使用已有项目

点击左侧项目名称，中央显示该项目图集。点击图卡打开图表，或使用图卡下方的 **查看代码与数据**、**直接查看 CSV**、**修改历史**。

大图会在中央图片区域内缩放，特别大的图会单独占一行。预览缩放不会改变导出尺寸。右侧候选图可以点击图片，在新页面查看完整图像。

### 上传 Python 代码与数据

1. 点击左上角 **＋ → 上传 CSV / Python 项目**。
2. 选择“新建项目”或已有项目。新建时填写项目名称和项目 ID，ID 建议使用英文、数字和下划线。
3. 分别选择 **code · 绘图代码文件夹**与 **data · 数据文件夹**。数据支持 CSV、TSV、JSON。
4. 如有原图，可选择原图文件夹。同名原图可直接用作图集预览，其他图会尝试生成预览。
5. 点击 **开始拆分并上传**，完成后检查项目图集。

代码应能在当前环境运行，数据路径应适合项目目录。遇到找不到文件、缺少依赖或无法拆分的提示时，请保留错误信息，联系提供代码的人或维护者。上传后先保存到本机，尚未自动发布给团队。

## 4. 用对话修改图表

### 完成一次改图

1. 在图卡上勾选要修改的图。只修改一张时，确认右侧“当前目标”就是这张图。
2. 在右侧输入具体要求，点击 **生成候选**。Enter 发送，Shift + Enter 换行。
3. 等待生成、渲染和检查完成。生成过程中，中央仍显示已经应用的正式图。
4. 查看右侧候选；必要时展开 **查看上一版的图**、**请留意**、**修改理解与检查结果**。
5. 满意后点击 **应用此版**，中央正式图及相应代码才会更新。

每张图、每轮 Chat 改图最多尝试调用模型 **3 次**，格式修正和自动修图共用这个额度；成功或需要你补充信息时会提前停止。批量操作按图分别计算，下一轮发送需求会开启新一轮额度。这个限制适用于 Chat 改图，不应理解为所有功能的统一调用上限。

### 推荐的需求写法

尽量说清“改哪里、改成什么、保留什么”。例如：

> 把这张图改成小提琴图，使用每组全部原始样本。保留组名、单位、配色和显著性标注。

> 将图例移到图外右侧，避免挡住数据；其他内容保持不变。

> 统一这几张图的字体和配色，保留各图的数据、坐标含义和组别顺序。

一次可以包含多个要求，但复杂修改建议分步完成，方便判断哪一步没有达到预期。

### 基于候选继续修改

新候选可继续修改时，会标为 **继续修改的起点**。可以直接发送下一条要求，也可以在其他候选上点击 **选此版本继续更改**。

例如：

> 基于当前候选，把图例移到右上方，并增加顶部留白，解决显著性标注重叠。

只有布局重叠或裁切问题时，通常仍可把候选作为下一轮起点。数据检查失败、渲染失败或正式版本冲突可能阻止继续使用该候选，需要先查看原因。

### 使用参照图

展开右侧 **参照图 · 只读**，选择参照对象，并在消息中说明参考哪些外观属性。例如：

> 参照图 A 的配色和图例位置修改当前目标图，保留当前图的数据、组名和坐标单位。

参照图不会被修改。若希望模型直接查看图片，需要配置支持图片输入的模型并开启图片传输。

### 批量对话修改

勾选多张图，点击 **批量对话修改**，再输入共同要求。生成后逐张检查并应用；批量生成不会自动确认全部结果。

切换选择范围后，请再次查看右侧目标和当前会话，避免把针对某一张图的要求发送给另一组图。

## 5. 如何理解提示与提问

候选旁边的文字用于解释模型理解、检查结果或需要补充的信息，并不都要求你回答。

| 提示或状态 | 含义与操作 |
| --- | --- |
| 候选 · 待审阅 | 可以检查图片，满意后应用，也可继续修改 |
| 需要你确认 / 需要补充上下文 | 查看具体问题，补充目标、数据列、分组方式或取舍后继续发送 |
| 发现布局冲突 | 检测到重叠或裁切，可继续要求调整位置、留白等 |
| 部分布局未能自动确认 | 自动检查有覆盖限制，需要人工查看图片 |
| 检查未通过 | 展开原因，区分布局、数据或其他检查问题 |
| 图像变化未达要求 | 本轮没有检测到足够变化，或目标效果未被实现；明确指出仍未改变的部分再试 |
| 已满足要求 | 当前已验证版本已符合这次简单要求，可能直接复用已有结果 |
| 正式版本已变化 | 原候选依据的正式代码或数据已更新；如有按钮，可“从最新正式版重试这轮修改” |
| 渲染失败 / 生成失败 | 查看错误；检查数据、依赖、API 连通性或输出是否被截断 |

**布局看起来可以接受时：**先展开“请留意”检查具体位置。如果界面提供 **仍按要求执行**，点击表示接受列出的重叠或裁切，会发起相应处理；后续仍需查看结果并应用。接受布局例外不会豁免数据检查等其他要求。

**已有候选被旧检查结果拦住时：**如果提供 **重新检查此版**，可用当前规则重新出图和检查。这一步不调用模型，也不会自动应用。

**转换图型仍失败时：**明确指定目标图型、分组列和样本列。当前完整样本自动核对主要覆盖可解析 CSV 分组的单子图箱线图、小提琴图；多子图、自定义绘图或其他来源可能无法自动确认。图看起来正确不等于样本和标注已通过核对，遇到无法核对时请将检查说明交给维护者，不建议反复发送同一句话。

## 6. 批量标准化样式

1. 勾选一张或多张图，点击 **批量标准化**。
2. 选择合适的标准化 Skill。
3. 等待候选生成，逐张检查字体、间距、图例、坐标轴和标注。
4. 满意后逐张 **应用此版**，也可继续通过 Chat 调整。

左下角 **查看、上传或删除 Skill** 可管理规则。上传时填写名称、ID，选择 `SKILL.md`，并按需附加样式配置 JSON。

标准化检查通过不代表所有视觉效果都达到要求；仍应检查字体替代、文字缺失、标注重叠等信息。

## 7. 手动修改、导出与历史

### 手动修改代码

打开图卡的 **查看代码与数据**，切到 **绘图代码**，修改后点击 **保存代码**。这是直接验证并保存代码的入口，请先确认当前图和编辑内容；希望先看候选时，使用对话改图流程。

### 导出图片

选择具体图表后，使用页面上方 **导出 SVG** 或 **导出 PDF**。需要导出某个候选时，应先应用该候选，再从正式图导出，避免导出旧版。

常规 Matplotlib 图可保留原生矢量内容；部分 Bundle 渲染器只提供 PNG，其 SVG/PDF 导出属于位图封装，放大清晰度仍受原图分辨率限制。

### 查看与恢复历史

点击图卡 **修改历史**，可以查看历次图片。带有 **恢复此版本代码** 按钮的版本可以恢复为新的当前版本。应用通常保留最早、上一轮和当前代码，不保证每张历史图片都有对应可恢复代码。

**完成并清理** 或 **修改完成，清理旧历史** 会清理应用中的旧版本文件；仅在确定不再需要这些历史时使用。已有 Git 提交仍可追溯，但网页不提供完整 Git 历史恢复操作。

## 8. 与团队共享修改

### 首次准备

1. 确认自己的 GitHub 账号具备团队仓库权限，并已在本机配置 GitHub 的 Git 登录。App 内置 Git，但不携带开发者的账号凭据。
2. 点击右上角 **团队协作**，填写协作者姓名和 Git 提交邮箱，点击 **保存协作者身份**。
3. 检查顶部同步状态。打开或刷新网页时，会尝试获取团队最新项目。

**应用版本分支与团队项目分支不同：**v0.1.3 是本次应用发布版本；当前随包配置的团队项目共享位置是 `Bonbonwjj/GraphicEditing` 的 `main` 分支，以“团队协作”窗口实际显示的位置为准。

### 发布结果

1. 对需要发布的候选先点击 **应用此版**。
2. 检查所有项目中已保存的修改，包括新上传的代码和数据。
3. 打开 **团队协作**，填写本次修改说明。
4. 点击 **将全部项目修改合并到团队版本**，等待发布成功。
5. 其他成员打开或刷新平台后获取结果。

该按钮发布的是全部项目中符合共享范围的已保存修改，不仅是当前选中的图。正式代码、数据、图片和历史会共享；未应用的 Chat 候选、对话与个人模型配置不参与同步。

如果提示双方修改同一文件，请记录冲突路径并与协作者协调。当前没有网页逐行合并界面，程序会停止以保留本机文件；不要反复点击发布或自行覆盖他人文件。

## 9. 进阶功能：Bundle 与共享模块

不使用 Border / Group 数据的用户可跳过本节。

### 导入 Border / Group Bundle

选择 **＋ → 导入 Border / Group Bundle**，填写项目 ID、名称，选择含 `manifest.json` 的 Bundle 文件夹，并指定包含 `behavior_analysis` 文件夹的运行时代码目录。确认来源可信后导入。

浏览器上传上限为 500 MB，较大的 Bundle 可选择 **从本机目录复制**。导入的数据先保存在本机项目中，发布后才与团队共享。GitHub 发布仍有单文件 95 MiB、共享项目总量 2 GiB 的限制，当前未接入 Git LFS。

### 修改共享绘图模块

在项目树打开共享模块，可手动编辑或输入要求后点击 **生成修改建议**。随后点击 **验证并生成候选**，检查预览和影响范围，勾选 **我已检查本轮候选图片和影响范围**，最后点击 **应用此候选**。

共享模块可能影响多张图。默认根据修改位置选择验证代表图或全部图，也可勾选 **本次强制验证全部图**。验证过代表图不等于所有图都已检查；修改涉及通用逻辑时，建议检查全部受影响图。



## v0.1.3 改图补充

不需要先查具体字号或轴线宽度。可以直接输入“字大一点”“X轴标题小一点”“坐标轴粗一点”。支持的单坐标轴图会按当前实际设置增减约一档（放大为当前的 1.2 倍，缩小为除以 1.2），生成预览；连续调整会累计。此路径无需模型调用，仍执行数据与布局检查。复杂多对象请求继续由模型处理。

图型转换未能核对时，请查看具体原因：

- **原数据已找到，候选使用情况未确认**：文件存在，但还没有证明新图实际使用了正确完整的样本。优先基于已有数据修复，无需重复上传。
- **现有汇总数据不足以还原分布**：只有均值、误差等汇总值，无法还原小提琴图所需的原始观测值。需要提供原始样本或选择合适图型。
- **部分组的样本数量不足**：例如小提琴图某组只有一个观测值，需要更多观测或更换图型。
- **需要定位原始样本来源**：来源暂未定位，可能在代码、Bundle 或其他列中；这不代表数据不存在。

源文件可读取不等于转换已核对通过。实际样本不一致仍会拦截；明确不足的数据不会通过反复模型重试来补造。

### 换图型的默认样式

直接说“改为小提琴图”或“改为箱线图”时，平台会复用标准化 Skill 的适用样式模板，并在候选里标注“样式依据”。不必每次重述线宽、字号和内部统计线。两组小提琴默认使用 Q1、中位数、Q3 实线与 Q1–Q3 竖向连接线，中位数横线是另外两条的两倍长，线段保持在轮廓内。用户明确提出的外观要求优先。没有匹配模板时会说明限制，不强制套用两组布局。

### API连接状态

顶部“API配置”同时显示连接状态：未配置、检测中、已连接、服务可达、连接异常或状态待更新。已连接表示最近两分钟内有成功的模型请求；服务可达表示连通性正常，但不能据此保证当前密钥、模型和出图请求均可用。配置窗口显示检测时间及具体失败提示。

页面可见时，每20秒通过HEAD请求检查服务连通性（不发送绘图数据、不生成模型文本）；页面每3秒同步检测结果。首次检测、断线恢复和手动测试发送一个最多8输出token的固定短请求，可能产生少量API用量。常规心跳不会重复执行该短请求。断连通常在约20–30秒内显示，实际改图调用报错或浏览器离线会更快反馈。后台标签暂停轮询，恢复可见后重新检测，不把过期状态当作已连接。


## 上传参考图片进行 Chat 改图（本地新增）

1. 选中需要修改的已有图表，在对话输入框上方点击“＋ 参考图片”，选择 PNG、JPEG 或 WebP；也可以把剪贴板中的截图粘贴到输入框。
2. 每次最多附带 3 张、每张原文件不超过 6 MB。上传后会显示缩略图，可点击 × 从本轮参考列表移除。参考图会自动缩放，并去除原文件附带的图片元数据。
3. 在顶部 API 配置里启用“改图时将当前图和参照图传给支持视觉的模型”，并使用支持图片输入的模型。未开启时，平台会明确提示，不会仅根据文件名假装看过图片。
4. 输入例如“参考这张图的配色、图例和布局，把当前图改成类似的样式，保留当前数据”，生成候选并审阅。多张图可按缩略图顺序称为“参考图 1、参考图 2”。
5. 参考图用于外观借鉴；数据、分组、单位和统计量仍来自当前项目。若要换成需要原始样本的图型，而项目只有汇总值，平台会说明缺少的数据。候选通过检查后点击“应用此版”。

参考图片会保存在当前项目的本地 Chat 资料中，随本轮消息记录保存；重新打开会话仍可查看。切换目标图不会把另一目标的参考图自动带入；同一会话中保留的参考图会继续作为后续对话上下文，后续不需要时可移除。
# 配对连线与半小提琴改图

当前操作方式：候选只要有代码，就能点击“应用此版”或“选此版本继续更改”；检查结果、旧版本和各种差异只作提示，不禁用操作。没有生成图片的候选也能继续改代码，点击应用时会先尝试执行出图，执行错误会明确返回。应用前的正式版本仍保存在历史中；应用不会额外弹出审阅确认。

上传参考图后，候选卡片会展示“读图与关键特征对照”：参考图可见特征、读图依据、候选实际表现和比较结果。外观一致、有差异或尚未确认都可以继续修改；通过数据检查的候选可应用，有展示检查差异时使用“应用此版”。数据错配、运行失败和正式版本冲突仍需先解决。

首次参考图改图通常包括读图、生成代码、候选视觉对照三次模型调用；同一会话、同一参考图片版本会复用已提取特征。若三次预算用于修复，或视觉模型连接失败，界面会明确标为尚未完成视觉对照；不能将其理解为已匹配。点击“重新检查此版”可重新渲染并更新视觉对照，可能调用视觉模型。

若当前数据是同一受试者的两个条件，可说明“这是配对数据，参考图改成半小提琴加配对连线，保留当前指标和统计标注”。平台对可识别的长表先筛选当前指标，检查每个条件中受试者 ID 是否唯一，再按 ID 连线。无配对关系时说明“这两组独立，不要连接观测点”；参考图中的连线不会作为配对依据。

缺少一侧观测的受试者，其已有观测仍保留在组内分布和散点中，仅不画连接线；重复受试者记录不会自动平均或去重。检查会显示当前指标的样本数、完整配对数及缺失配对数量。半小提琴被坐标范围压缩到不可见时，候选会被要求修复。自定义图或未识别的数据结构仍需明确数据来源，不能把检查通过理解为实验配对设计已获独立确认。
