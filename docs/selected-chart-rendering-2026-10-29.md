# 只按选中图按需渲染

图库可见性过去会触发常规 preview 请求。对于缓存失效的普通、native、universal 工程，这意味着滚动浏览即可重新运行多张图的原分析。项目启动及部分导入路径还会预热整项目。它们与正在生成的改图候选争抢 CPU、磁盘和内存。

现在的执行规则：

- 图库自动请求只使用 `preview?cached_only=1`。后台验证已有缓存并读取图片；缺少缓存、缓存失效或请求历史源码时返回 HTTP 204，绝不执行绘图。即使请求同时含 force 参数，也优先遵守 cached_only。
- 缓存缺失的图卡显示“点击此图按需生成预览”。打开某张图或明确刷新时，前端才发送允许绘图的请求，目标仅为该图。
- 后台缩略图读取不会覆盖正在进行的所选图加载，也不会为同一图再启动一个普通加载。
- 启动时仅显示工程，不自动渲染默认工程的第一张图；进入工程的明确操作仍可打开该工程的一张图。
- 启动及导入后不再预热全部图表。旧 warmup hook 保留为空操作以兼容现有调用者。
- 改图会话继续按当前所选图或明确勾选的批量范围执行；只读参照图不作为编辑目标。

验证：66 项后端回归通过；前端状态及图库请求回归通过；真实浏览器以 20 张临时图验证启动渲染 0 次、滚动触发未选图渲染 0 次，选中 chart01 和 chart05 时各渲染一次，无页面脚本错误。浏览器使用固定图片替身记录渲染调用，不运行外部模型或真实科学计算，因此不据此承诺固定秒数提速。

边界：选中图自身仍需科学数据/布局验证。通用适配器若依赖原分析，仍会执行其共同计算，后续输出也可能需要经过前面的构图代码；本次关闭的是额外图卡与整项目预热触发的独立渲染，尚未实现分析结果与绘图输入的完全分离。
