# 改图软件改进记录

## 已完成

- 改图 Skill 与 compact_v1 输出协议统一，去除重复的完整源码/元数据要求。适配器、字体坐标轴和大数据规则按请求显式加载，而非仅写文档链接。
- 使用同一模拟配色请求，prompt_chars 从35430降为14167，约减少60%。这是请求字符数，不是实际token计费或服务响应时延的测量。
- 通用拆解对通过两次图片、图元、读取依赖一致验证的输出缓存。缓存由所有导入文件内容、Python与已安装包版本、平台绘图代码、布局配置、入口和预览DPI共同确定。数据变化或缓存内容损坏重新试绘。
- 失败的逐入口诊断持久化，避免只有总错误而丢失每个入口的失败原因。
- 记录实际保存文件/行号/函数来源。跨入口重复图片需要保存位置及图元一致才去重，防止独立图仅因外观相同而丢失。
- 原脚本命令行参数缺失时提供可读退出原因；修复跨平台测试/运行中的Windows文件夹选择常量兼容。

## 继续改进的优先顺序

1. 适配交互式工程：将TkAgg、数据目录选择、命名和必填CLI参数显式映射到工程运行配置。adaptive_foraging已通过大文件导入，但仍需这部分适配；当前不能声称它已完成拆解。
2. 提取稳定绘图输入：在原分析完成后导出完整绘图数组和统计值，使后续改图不再重跑分析。必须比较原输入与导出输入，避免把双次复现误称为等价验证。
3. 减少大数据复制：当前仍完整备份与建立快照。后续引入具有隔离边界的只读数据挂载、依赖变更检测与按图数据包，降低大工程的磁盘I/O。
4. 改善任务控制：通用拆解增加停止/恢复和按失败入口重试；缓存已提供输出复用，但尚未构成完整断点调度。
5. 处理历史测试分歧：全量测试中已有的数据派生/候选应用策略与旧测试期望需要单独梳理，保持产品行为与验证标准一致。

## 验证方式

Skill结构验证、模拟模型请求验证、缓存命中/数据变化失效验证、失败诊断验证、相同图片独立图保留验证、真实bubblewrap多图拆解及候选改图，以及工作区/导入HTTP回归。不以正则匹配规则文字代替实际渲染与数据比较。
