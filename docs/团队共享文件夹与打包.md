# 团队直接共享工程与启动说明

当前平台版本为 v0.3.0（2026-11-10），发布到 GitHub 的 lc 分支。包含绘图类型切换、组别样式联动、正式历史保留、子图与文字拖动、拖动实时跟随、散点和配对连线位置联动，以及直接共享工程。

## 团队如何使用

1. 每位成员将 `Plot-Forge-v0.3.0-team.zip` 解压到自己的本机目录。此包不含 Python 运行时，电脑需要 Python 3.11 或更高版本。双击 `Start-Plot-Forge.cmd`，首次启动联网安装依赖。
2. 在每台电脑的资源管理器确认能够访问同一个 `X:\figure_DATA_code`。程序固定直接使用这里的 `projects`，不是各自的项目副本。
3. 打开应用选择 `jiahui` 工程。交互修改点击“确定并同步代码”，Chat 候选点击“应用此版”，结果就保存到公共文件夹，无需再上传或拉取。
4. 其他成员重新选择图表，或使用“团队协作 → 刷新共享工程”，即可读取更新。刷新前先保存自己的当前修改。
5. 可在“团队协作”保存各自姓名，用于正式历史记录。各自的 API 配置和账号登录保存在本机程序或系统密钥库，不放进公共目录。

每人运行自己的本机程序，大家打开的是公共盘中的同一份工程。不要从公共盘运行同一份程序目录，以免混用账号和模型设置。

## 并发保存与历史

同一个工程的应用写入使用跨进程文件锁。保存图表时还核对页面读取的代码版本；如果其他成员已经保存新版本，旧页面的保存会停止，保留公共目录中的新版本，要求重新加载后再编辑。Chat 候选也会检查生成时的基础版本。

这不是多人同时操作同一画布的实时协同编辑器。可以分工修改不同 Figure；同一 Figure 最好先协调。同一时刻的写入会串行处理，不会自动合并同一张图的两份不同修改。应用以外的编辑器不受应用锁约束，使用外部编辑器时请额外协调。

正式代码、初始/上一版/当前版等已有正式历史及图片均保存在公共工程。只有明确点击“定稿／清理历史”才清理该图旧历史。此操作作用于全团队共享的工程，请按团队约定使用。

共享盘不可访问时，程序会提示连接问题，不会偷偷切换到本机副本，避免成员各改一份却以为仍在共享。

## 公共目录

```text
X:\figure_DATA_code\
  projects\
    jiahui\
      project.json
      data\                 # 冻结绘图输入与资源
      charts\               # 当前正式绘图代码
      lib\                  # 绘图依赖与原生源码
      history\              # 正式代码与图片历史
      previews\             # 当前图片
      .chat\                # 在这个共享工程中新建的会话与候选
    .write-locks\           # 应用的跨进程写入锁文件
```

程序目录中的 `team_collaboration.json` 指定 `mode: direct` 与公共目录路径。若团队的盘符映射不同，可由维护者统一改为所有电脑都能访问的 UNC 路径。

公共工程初始包 `figure_DATA_code-initial.zip` 只用于初始化空的公共目录，解压后应直接得到 `projects` 文件夹。公共目录已有工程时，不要用初始包覆盖已有文件。后续编辑直接在应用中保存，不用反复解压。

## 打包与原工程保留

程序包按当前磁盘上的最新修改生成，不依赖 Git 提交。v0.3.0 的公开平台包不包含 `jiahui` 研究工程，直接共享模式实际使用的是公共目录里的现有工程。原电脑的本机工程没有删除或移动。此前 v0.2.3 团队包与初始工程备份保留在公共目录的软件包文件夹中。

公共工程中保留正式代码、冻结输入、图片与正式历史。研究工程、虚拟环境、账号凭据、模型配置、Git 检出、日志、隐藏 Chat 会话和未应用候选、原始分析准备副本不进入公开平台包。原本机候选和原始分析副本仍留在原电脑；在公共工程中新建的 Chat 会话与候选会位于公共工程的 `.chat` 中。

冻结代码与数据逐字节保留，不转换换行，也不重算统计结果。可用 `SHA256SUMS.txt` 核对 ZIP 完整性。
