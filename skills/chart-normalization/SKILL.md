# Chart normalization

## Purpose and inputs

Normalize an already imported chart script. The upload flow owns file import; this skill owns the style change. Read the entry script, called local drawing functions, relevant CSV schema, existing image if available, source revision, and the versioned style profile supplied in the normalization request. The bundled profile is [`assets/style-profile.v1.json`](assets/style-profile.v1.json). Use its exact values. Consult [chart-type rules](references/chart-types.md) for template applicability.

The uploaded chart type and scientific artist composition are hard constraints except for the data-supported missing error bars and violin quartile marks described below. Keep the same axes, existing layers and artist kinds, number and order of data series, group order, paired connections, x/y values, filtering, existing statistical calculations, labels, units, and existing fitted model. Do not turn an unknown chart into a known template. Do not add an error bar because an example preview contains one. Do not add a fit when the source has no fitted model, regardless of CSV size. If the source has no p values or comparison definition, do not invent significance marks.

For paired-subject plots, preserve the existing validated data path. If data preparation must be reconstructed, use the shared `paired_plot.prepare_paired_data` / `load_paired_data` API and the Harness `paired_plot_data` contract: filter the current metric first, split conditions, require a unique subject ID within each condition, then align by ID. Never connect rows by their order, silently average duplicate IDs, or mix metrics that share group names. Retain unmatched observations in group distributions/scatter; only complete ID pairs may have connectors, and report unmatched counts. ID overlap alone does not establish a paired experimental design. Use `draw_paired_plot(..., half_violin=False)` for a matching paired-scatter template or `half_violin=True` only if half violins already belong to the source/request. Preserve other existing layers; do not convert a chart merely to use the helper.

The profile is the source of truth for fixed dimensions and visual tokens. Data-dependent values and labels may differ between charts. Remove any top figure title from the rendered figure and preserve its text in chart metadata or the change report. Do not use `bbox_inches="tight"` for a fixed-size template: it makes output dimensions depend on label length. Report overflow rather than silently changing font size or canvas size.

## Fixed visual rules

1. **Significance.** For existing, identified comparisons: `p < .001` → `***`; `.001 ≤ p < .01` → `**`; `.01 ≤ p < .05` → `*`; `p ≥ .05` → `n.s.`. Use the project's specified p-value source and test. Keep the existing statistical method. A heatmap comparison may belong to any cell, not just the diagonal. A project may compare a cell with the mean of other cells in its row only when its data and comparison definition support that calculation. Center each mark visually inside its own cell in both directions; apply the profile's fixed star glyph offset when necessary.
2. **Axes.** Use the profile's `3.4 pt` spine width. On ordinary Cartesian plots, the y spine runs from the first to last visible major tick. The x spine does the same except bars retain a complete baseline. Move the x spine, ticks, and x label down together by `12 pt` relative to the plotting rectangle, leaving the data and y axis in place. This is a physical translation, not a constraint on the shortest distance between trimmed spine endpoints; do not shift the y axis left or distort tick/data geometry to enforce an endpoint gap. Heatmaps are exempt: all four spines touch the matrix outer edges, enclose every cell, and extend beyond the center of outer-category ticks.
3. **Heatmap colorbar.** Place it on the right. Align its top and bottom with the *rendered matrix* top and bottom, including any shrinkage from equal aspect ratio. Use the profile's width, gap, labels, and ticks.
4. **Typography.** Use the platform-provided `STHeiti` font for every visible text artist, including labels, ticks, legends, annotations, and significance marks. Do not silently fall back to a project or Matplotlib font; if the platform font is unavailable or lacks a required glyph, report the exact text and do not mark the candidate as meeting the fixed style. Ordinary axis labels are `17.5 pt`, black; heatmap labels are `22 pt`, bold. Numeric ticks are `19.5 pt`; category ticks are `16.25 pt` unless a chart-specific override exists. Preserve the actual label text and units. Do not add a title for an axis that has none.
5. **Two-group geometry.** Where the two-group template genuinely matches, centers are `0.82` and `1.18`, box/bar width `0.133333` categorical x units, edge gap about `0.226667`, outline `3.2 pt`, box median `3.1 pt`. Preserve group order. More groups require their own template.
6. **Ticks and existing artists.** A continuous numeric y axis has at most five visible major labels. Keep all data, whiskers, errors, and annotations in view. Apply the profile's widths, marker sizes, colors, error caps, violin marks, heatmap frame, legend, canvas, background, and export resolution to matching *existing* artists. Do not change the statistical meaning of color, size, or line type.

7. **Data-supported missing error bars.** For a line chart without error bars, add them if the stored CSV explicitly supplies error values and meaning. Uploaded CSVs contain prepared plotting data. A derived uncertainty is allowed only when its intended meaning and all required aggregate fields are explicit: for example, derive `SEM = supplied sample SD / sqrt(supplied n)` only if SEM is requested/defined, n belongs to the same aggregate, and n is a positive integer (at least two for a supplied sample SD). Do not select SEM by default, treat plotted rows/means as replicates, re-estimate the supplied mean/SD, or introduce a new statistical method. For CI, preserve the supplied bounds/confidence definition; do not invent a confidence level or infer CI from SD without an explicit existing formula. Preserve existing error-bar values and meanings. Never estimate values from the rendered image. If the CSV cannot support the calculation, still render the chart and report the missing uncertainty columns, derivation inputs, error meaning, or group mapping and that error bars were omitted. For scatter, normalize an existing fit's appearance while preserving its model, coefficients, groups, and range; an absent fit is not a missing-data warning.

8. **Multiple panels on one canvas.** Preserve panel count, order, chart types, and data. On the exported image, every horizontally adjacent pair needs a clear gap of at least **twice the larger visible Y-axis-title-to-Y-spine distance** of the two panels; every vertically adjacent pair needs at least **twice the larger X-axis-title-to-X-spine distance**. Measure clear space between the panels' outer visible content, including axis labels, ticks, legends, and annotations. This is a minimum, not a fixed grid template. Adjust panel spacing, margins, or the multi-panel canvas when needed without shrinking fixed font sizes or clipping content. If the relevant title/spine or adjacency cannot be identified, report the rule as unverified; if the required gap cannot fit while preserving the figure, report the conflict and do not mark it compliant. Batch normalization applies this check to each figure that contains multiple panels; separate selected images are not treated as panels of one figure.

The profile also defines chart-specific line, scatter, violin, histogram, grouped bar, and heatmap values. For a matching violin with stored q25/q50/q75 (preferred), or explicitly supplied observations used to draw the existing violin, its internal marks show the 25th, 50th, and 75th percentiles, with a vertical connector from q25 to q75. The median horizontal line is twice as long as each outer horizontal line; keep all three inside the violin body. Preserve any existing scatter or other internal layers. Without stored quantiles or the existing plotting observations, or without a confirmed matching template, do not guess these quantiles or reconstruct them from mean/SD. Keep the existing density and bandwidth; do not synthesize a density from quartiles.

## Unsupported or unfamiliar charts

Apply only rules whose targets can be identified safely. A pie, map, polar plot, 3D plot, broken axis, network chart, or unconfigured multi-panel chart must retain its composition. Do not force ordinary 2D axis geometry onto it. Even without a whole-chart template, check measurable adjacent panel gaps under rule 8. If a chart has no matching canvas or artist template, keep that part of the original layout and report `missing_template` or `not_applicable`. It can still be `partially_normalized` when common, safe visual rules were applied. Keep existing legends when their exact placement is undefined.

There is no default uncertainty meaning for newly added error bars; use the meaning explicitly supplied by the CSV schema/project or user. Do not replace an existing error meaning or fitted model. Do not change histogram bins, violin bandwidth, heatmap colormap or color limits, or whether to hide outliers. The `RdBu_r` example colormap is not a normalization rule: keep the source heatmap and colorbar colors.

## Workflow and output

1. Identify the entry script, called style functions, data inputs, axes, artist inventory, overlays, comparisons, and the code that controls each visual property. Treat shared helpers and CSVs as read-only. Prefer existing parameters or target-local adapters, and report dependencies. A project-wide request is a set of explicit chart targets, not permission to rewrite a shared helper. If an isolated change is impossible, report it rather than affecting unselected charts.
2. Match the whole-chart template only when chart type, group count, and panel count agree. Otherwise use safe common and artist-level rules. Make the smallest source change that can be rendered by the workbench using `CHART_PROJECT_DIR` and `CHART_OUTPUT`.
3. Return exact, uniquely anchored source replacements when possible; the Harness reconstructs the complete candidate Python source. If exact replacements cannot express the change, return the complete candidate source. Include a concise change list, unsupported rules, and warnings. The workbench renders the candidate before saving. Never claim that the model itself rendered or visually verified it.
4. After rendering, compare data columns, calculations, plotted values, artist composition, scientific labels, and visible figure properties with the original. A changed chart type, lost original layer, altered existing fit, or invented comparison is a failure. The only permitted scientific-summary artist additions are the data-supported error bars and violin quartile marks above; significance text may represent existing identified p values. Record their data source and computation, actual rule values, output dimensions, the actual font used in the export, missing glyphs, and any unverified rule. A missing fixed font or glyph is an unmet rule, not a successful preview.

The workbench stores a separate candidate preview after syntax, scope, data, structural, and render checks. Never apply automatically: the user must explicitly apply a specific candidate version, with a fresh base-version/dependency check. The original code and image remain unchanged during preview or failed validation. If a rule cannot be applied without altering scientific content or the candidate cannot render, report the limitation and leave the original chart untouched.


## Runtime helpers

The workbench supplies `studio_style`. `apply_normalization_style()` sets defaults before drawing; `finish_normalized_figure(fig, CHART_OUTPUT, chart_type=...)` applies safe geometry and exports a candidate. It rejects a single-panel template for multi-panel, twin-axis, or non-Cartesian layouts by preserving geometry and recording a warning. It does not infer artist roles or prove all rules satisfied. Apply identified artist-level widths/markers/comparisons explicitly and report unverified rules.

Optional `plotting_error_values(rows, specification)` accepts explicit SD/SEM/CI mapping or supplied sample SD+n to explicitly requested SEM; it returns `available` or `unavailable` with columns/formula/reason. It never chooses SEM or treats rows as replicates. Optional `add_normalized_violin_quartiles(ax, bodies, positions, quartiles)` draws supplied q25/q50/q75 and IQR connectors with the fixed half-length ratio inside identified bodies; use only when these marks are missing, never duplicate existing layers.
