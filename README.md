# Plot Forge · 共享科研图表工坊

使用说明：[当前功能与操作指南](docs/Plot-Forge功能说明.zh-CN.md)。

团队通过 GitHub 共享绘图代码、数据、图片和正式修改历史；每位成员使用本机 Python 执行绘图，在本地网页中上传、查看、修改、预览和发布。默认不需要 Docker。

## ChatGPT 订阅与本地工程准备

已拆分工程从“打开已拆分工程”直接进入；旧版已有 `charts/*.py` 的工程继续兼容。未完成的导入只显示在“新建 / 继续拆分”中，标准备份恢复后无需重复发送源码。

`main_figure_plotting_package_20261016` 是受支持的独立冻结绘图包，使用本机直接适配，无需模型分析。原始源码逐字节保留在 `lib/native/`，冻结输入及 SVG、字体、PPTX 等资产在 `data/native/`，每图一个 `charts/figN.py`，在其 `customize(figure)` 中修改显示元素。Fig1 保留原生统计轴和已批准的任务示意栅格。原入口所需的临时文件只在运行副本中生成，全部图试绘通过后才显示为可打开工程；失败重试可复用依赖未变的已验证图。

此绘图包使用独立 `.native-venv`：`python -m venv .native-venv` 后，用该环境的 pip 安装 `requirements-native.txt`。它保留原包声明的 Matplotlib/NumPy 等版本，不改变应用环境。Linux 原生图强制使用 bubblewrap 系统沙箱：网络隔离、输入快照和 Python 依赖只读、临时输出可写；未安装 bubblewrap 时停止并提示，不自动退回无沙箱运行。每次原生图渲染上限为 150 秒墙钟时间、120 秒 CPU、30 MiB 单个输出文件；数据和输出数验证照常执行。

打开应用时可选择“继续已有工程”，或选择本机工程文件夹。新增的“打开工程”入口默认建立**仅本机**工程，不参与团队发布和桌面发行包。原有团队项目的同步行为不变。

### 连接模型与隐私边界

在顶部“API 配置”选择 API Key 或 ChatGPT 订阅。ChatGPT 使用官方 Sign in with ChatGPT OAuth（PKCE、state、nonce 与 ID Token 签名校验），只在 `auth.openai.com` 登录；不收集 ChatGPT 密码，不读取浏览器 Cookie，不使用逆向接口。凭据保存在系统密钥库，失败时仅存后台内存；不写入工程、浏览器存储或备份。刷新、退出与撤销失败会有状态提示。

登录后点击“读取可用模型”，选择账户返回的模型，单独勾选“允许发送代码”后保存。测试连接仅发送 `Reply OK.`。未授权外发时分析/改图被阻止；不支持的账户、额度耗尽或断流都不会自动改用付费 API。

**不能保证零泄露风险。** 云端改图需要发送相关源码、绘图数据/结构、对话，以及你明确勾选的图片。提取分析只发送已列出的 Python 源码和数据文件名，不发送原始数据文件，但源码中可能内嵌敏感信息。常见凭据检测只能辅助拦截，不能证明代码无秘密。`store:false` 不代表零保留或不用于训练；须核对账户数据控制和单位政策。需要代码完全不出本机时，应配置本地模型，并审阅所执行的 Python。默认本机 Python 不提供 OS 沙箱，恶意程序可能访问用户文件；推荐为不完全可信的代码配置 Docker 隔离。不要把本应用目录放在自动同步的公共网盘中。

截至 2026-10-21，本接入依照官方订阅共享预览文档实现：支持范围、模型和用量取决于账户/工作区是否获准，**Pro 订阅不等于无条件获得通用 API 额度**。实际登录与计费资格必须由账户持有人确认，自动测试使用模拟授权，不证明真实账户可用。

官方参考：[登录流程](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[模型与推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)、[预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。

### 一次准备，持续改图

1. 选择工程文件夹，检查文件清单，再“备份到本机并打开”。工程以名称保存在 `projects/<工程名>/`；不会执行原分析。隐藏目录、符号链接、疑似凭据文件及不支持的格式不会复制，因而这不是原始科研工程的完整灾备。
2. 确认源码发送范围，运行随附的 `skills/plot-code-extraction/SKILL.md`。已有兼容 `CHART_PROJECT_DIR` / `CHART_OUTPUT` 的独立入口可以直接验证，不重写科学处理。普通分析工程生成且仅生成 `<name>_export.py` 和 `render_plot.py` 两个提取源文件。
3. 提取结果保持 `pending_local_run`：下载并审阅导出代码，放到原工程根目录，用原分析环境运行 `python <name>_export.py --output <新的plot-data目录>`。应用不会擅自运行原始分析或覆盖原始数据。
4. 选择本机 `plot-data` 目录并确认试绘。平台验证 manifest、相对路径、大小、SHA256、导出程序绑定、原始捕获值与导出值、图表 ID 集合，以及逐图单输出。验证失败保持待准备；只有全部通过后才可进入对话改图。验证是对提供的捕获证据的检查，不能证明模型没有改变科学计算或遗漏全部动态依赖。
5. 选择图表，在右侧对话输入修改（例如“将线条改为红色，保持数据不变”）；检查候选图，再“应用此版”。候选数据比较、冲突检查和正式历史沿用现有流程；NPZ 等二进制依赖也参与版本校验。
6. 下载标准 ZIP 备份，解压后选中其中的工程目录即可恢复。再次打开本机已有工程则直接继续，不重复提取。应用重启后，未完成的准备状态同样保留。
7. 删除工程：在“打开工程”中选择已有工程，点击“删除选中的工程…”。核对将删除的 `projects/<工程名>/` 工作副本与保留的原始路径，输入完整工程名称后确认。只删除本机工作副本（含拆分代码、数据副本、`.preparation/source/` 备份、预览、对话与历史），不删除原始文件夹或已下载的标准备份。删除不可撤销，想保留改图结果请先下载备份；未记录原始路径时会提示先确认是否另有原件。运行中的任务、符号链接/挂载目录、与原始路径重叠的目录会被拦截；保留私有工程登记和 Git 忽略规则，避免同名重导入意外公开。此操作不执行远端发布；团队工程的本机删除可能在后续手动发布时同步给团队，或在拉取时恢复。

工程名称与分析范围：

- **整文件夹拆分**：打开新备份副本后点击“规划整个文件夹（不发送源码）”。本机扫描将全部 Python 文件作为目标列入覆盖清单，递归补入本地依赖，再将完整文件分成不超过 18 万字符的请求；完全相同的源码正文用一份完整文本和所有原路径表示，不做摘要或截断。可解析的字面量 `sys.path` 设置参与定位，但静态分析仍不证明动态依赖完整。
- 检查批次范围并勾选独立的批量发送权限后，点击“开始 / 继续整工程拆分”。这是多次模型请求；每批结果保存在同一工程的隐藏准备目录，成功批次不会因其他批失败被覆盖。原样重试仅处理网络失败、中断和未提交的批次；缺少依赖的结果须先修正范围，不能重复发送相同源码。源码或计划改变时拒绝复用旧检查点，要求新建副本；单目标完整依赖仍超限时明确标为 blocked，不会跳过或关闭保护。
- 下载“全部批次提取方案”，审阅并逐批在原分析环境执行导出；每批输出到新的 `<统一导出目录>/<batch_ID>/manifest.json`。填写统一导出目录并确认本机验证。各批分别进行导出程序绑定、数据值与全部图表渲染检查；全部通过后，以批次前缀隔离图名和数据路径并重新试绘，才一次性安装到同一工程。失败时不安装部分图表，已通过批次保留，可修正导出包后重试。整个工程总数据仍受原有快照大小限制。
- 辅助、验证或编排脚本也在覆盖清单中，但不应伪造成图表；模型若无法确认其目标图表和依赖，会明确返回需要补充依赖，阻止全工程完成。规划成功不等于提取成功，生成成功不等于本机验证成功。整批流程不自动运行原工程，也不会写入原始文件夹。

- 上方“新建副本名称”只用于创建/打开副本，不会重命名已有工程。编辑它或源目录后会收起旧工程操作，避免误操作旧工程。重命名请选中已有工程，在“当前工程显示名称”中修改并保存；列表和标题更新，工程 ID、目录、候选与历史路径不变。
- 超过单次 18 万字符时，无需删除原始工程或重新复制：在“本次分析的图组目录 / 入口文件”选择一个图组或完整入口文件。预览只在本机读取 AST，不执行代码、不调用模型；统计全部字符，递归补入能解析的本地导入及包初始化文件，完整列出发送源码、额外依赖、遗漏正文和只发送文件名的数据清单。
- 静态依赖扫描不是完整性证明：动态导入、歧义和语法问题会提示给用户与模型。模型仍须在证据不足时返回 `needs_context`；不允许伪造依赖或绕过后续原始绘图输入验证。补入依赖后仍超限则继续阻止提交，不截断文件。每次变更范围都清除发送确认；服务端核对预览摘要，源码变化时要求重新确认。
- 下方的单组模式仍只覆盖用户选择的范围，其他图组不会自动合并；需要整个文件夹时请使用上面的整批入口。完整原始备份仍保存在本机，未发送的源码正文不会随单组请求上传，但会发送工程内文件名以帮助模型识别缺失依赖。生成提取代码后仍需本机导出与验证，不会直接标记整个工程已准备完成。

标准备份采用 `<工程名>/data/` 与 `<工程名>/code/`；后者包含 `project.json`、`charts/`、`lib/`、`previews/`、`history/` 和 `validation/`。运行时仍使用现有应用兼容的 `projects/<工程名>/charts|lib|data/`，恢复时自动转换。OAuth 凭据、对话草稿、原始分析副本和隐藏准备状态不进入标准备份；原分析副本留在本机 `.preparation/source/`，请另行做原始数据备份。

当前边界：目录导入最多 2 GiB / 10000 个受支持文件；分析源码最多 18 万字符；验证包最多 100 MiB、100 张图；网页标准备份的未压缩文件总量最多 200 MiB，更大工程需拆分或使用本机文件管理器备份。NPZ 禁止 object dtype / pickle；CSV 需声明序列化规则；Parquet 需要本机额外安装相应引擎。提取图目前输出 PNG，SVG/PDF 需另行适配，不能冒充矢量格式。动态依赖、未提供文件或不能完整捕获的数据返回 `needs_context` / `unsupported`，不会补造示例数据。

验证命令：`.venv/bin/python tests/run_offline.py`，使用临时模型配置和虚拟密钥库，并阻断非本机网络；避免旧测试误用实际模型配置。前端回归使用新版 Node 运行 `tests/test_chat_frontend.js`。可选真实浏览器测试为 `tests/browser_workspace_smoke.py`（开发环境需 Playwright 和 Chrome，仅使用临时工程及模拟登录）。

## 桌面 App

打包版已内置 Python、绘图库和 Git，无需另行安装。完整解压后在对应系统上运行：Windows 打开 `Plot Forge.exe`，macOS 打开对应芯片版本的 `Plot Forge.app`，Linux 直接运行解压目录内的 `Plot Forge` 可执行文件。首次打开自动初始化环境并打开本地网页，之后双击即可使用。个人 API Key 和 GitHub 账号权限仍由各自配置，公司模型需要 VPN。

正式项目、候选和配置保存在用户目录，更新 App 时保留。构建方式与验收说明见 `docs/DESKTOP_APP.md`；下方 Python/Git 安装步骤仅适用于直接运行源码。

## 双击启动

首次需要安装 Python 3.10+ 和 Git，并下载本应用到一个可写目录。首次运行会自动创建 `.venv` 并安装绘图库，需要联网；后续启动复用环境，仅依赖清单变化时更新。

- **Windows**：双击 `Start-Plot-Forge.cmd`。
- **macOS**：双击 `Start-Plot-Forge.command`。若系统没有执行权限，首次在终端执行 `chmod +x Start-Plot-Forge.command`。
- 也可以在应用目录运行 `python launch.py`（macOS 使用 `python3`）。

启动器自动启动本地后台、打开浏览器，并复用已启动的同一工作区。默认地址为 `http://127.0.0.1:8765/`；端口被其他程序占用时自动选择其他端口。后台日志为 `local-server.log` 和 `local-server-error.log`。若希望使用特定 Python，启动前设置 `PLOT_FORGE_PYTHON` 为解释器路径。

每位成员分别保存一份本地应用和工作区，不要将 `.venv` 放进网盘共享文件夹。

5. 打开本地平台即允许使用本机 Python 运行团队项目，无需再勾选信任。上传或同步后可直接生成预览和修改候选。

连接只保存到本地 `.collaboration/`；同步使用其中独立的 Git 检出目录，应用自身未提交的代码不会被一同发布。默认将本机 `projects/` 下所有项目的已保存修改发布到指定共享分支；请检查项目列表，不要在该目录存放不打算共享的文件。一个工作区绑定一个仓库/分支，其他团队使用另一份本地工作区。

## 上传与协作修改

- 左上角 **＋ → 上传项目**，选择绘图 Python、已整理的 CSV/TSV/JSON 和可选原图。文件先保存到本机；上传者信息记入项目。上传后可直接运行。
- 成员可以查看和修改任意已拉取的图。Chat、批量标准化和手动代码修改沿用现有流程。
- Chat 候选留在修改者本机；继续对话可以基于候选修改。点击 **应用此版** 后才更新正式代码、图片和历史。
- Chat 从请求提交起每 1.5 秒刷新准备、模型生成、渲染检查和修正阶段，并显示等待时间。原图和候选在两个独立快照进程中并行渲染，以缩短本地等待；模型网络耗时仍取决于服务，数据、布局和版本检查不省略。
- 明确要求“折线→scatter/散点图”时，按同一坐标轴和唯一组名核对全部有序 `(x, y)` 坐标的摘要、点数、可见性、轴范围与标注，而非只比较三个示例点。漏点、改值、乱序、交换组别、隐藏点、额外元素仍被拦截；缺失值、自定义坐标变换或无法唯一对应的组暂不自动放行。旧失败候选可“重新检查此版”，不必再次调用模型。
- 每张图、每轮 Chat 改图最多调用模型 3 次，格式修正、补充参照上下文和自动修图共用这个额度；成功或需要用户补充信息时提前停止。批量图表逐张处理，不因每次仅有一个可写目标而要求用户重新选择第二张图。
- 仅因布局重叠或裁切未通过的候选会作为下一轮起点，可直接在 Chat 中要求基于此版修复，也可选择旧候选继续。布局问题解决或明确接受后才能应用；数据变化、渲染失败和版本冲突仍会阻止继续使用该候选。
- 明确要求转换为箱线图或小提琴图时，不再要求新旧绘图元素逐一相同：对可自动核对的单子图 CSV 分组，检查实际传入绘图接口的完整样本、组标签、单位与统计标注。通过后允许继续修改和应用；漏样本、改值、调换组别、篡改生成后的统计线条仍被阻止。不能核对的输入或多子图会说明原因，不报告已验证。隐藏箱线离群点时明确提示。旧的检查失败候选可点击“重新检查此版”，仅重新出图和检查，不调用模型。
- 在 **团队协作** 中填写修改说明，点击 **将全部项目修改合并到团队版本**。提交记录包含协作者姓名和邮箱；已应用候选的图表历史也记录修改者。
- 其他成员打开或刷新页面时自动获取结果。同步后可直接使用。

同步采用文件级三方比较：修改不同文件时可自动合并；双方修改同一文件、或一方删除而另一方修改时会停止，显示冲突路径，保留本地文件。当前不提供网页逐行合并编辑器，需协调后手动处理文件，再重试。发布使用普通 Git push，不会强制覆盖远端；若发布期间远端再次更新，提交会保留在 `.collaboration/repository`，需要先处理 Git 分歧。

GitHub 不负责执行 Python。代码在每位成员自己的电脑运行；需要的额外绘图库也需安装到本机 `.venv`。共享项目应使用相对路径，通过 `CHART_PROJECT_DIR` 读取数据，通过 `CHART_OUTPUT` 输出目标图。单文件限制 95 MiB，共享项目总量限制 2 GiB；本版不集成 Git LFS。

## 共享范围与本机执行

| 内容 | 保存位置 / 是否共享 |
| --- | --- |
| 正式代码、数据、原图、预览和历史 | `projects/`，发布后共享到 GitHub |
| 对话、未应用候选 | `projects/<id>/.chat/`，不参与同步 |
| 模型 API Key | 系统凭据库，不参与同步 |
| 模型地址、个人 Git 配置、同步基线 | 本机配置，不参与同步 |

默认 `local` 渲染使用本机 Python 子进程，有超时、基础导入检查和候选数据比较，**没有操作系统沙箱**。打开平台即允许运行团队项目及模型候选，重启或同步后无需重复确认。Python 代码以当前用户权限运行。

需要 OS 隔离时仍可选：macOS 设置 `PLOT_FORGE_RENDER_BACKEND=seatbelt`，或安装 Docker 后设置为 `docker`。Docker 镜像可用 `docker build -f Dockerfile.renderer -t plot-forge-renderer:local .` 构建；这些是可选高级模式。

## 模型配置

右上角 **API 配置** 默认填入 `http://10.254.1.138:8080/api/v1/chat/completions` 和 `glm-5.3`，可自行更改；需在可访问该内网服务的网络中使用。已保存的个人配置优先，也可点击“使用默认模型与地址”重新填入。API Key 由每位成员自行填写，不内置、不共享。可按需配置图片输入。测试连接只发送简短消息；正式改图按设置发送必要的代码、绘图数据及图片。模型 Key 保存在 Windows Credential Manager / macOS Keychain。也可使用 `OPENAI_API_KEY`、`LLM_API_URL`、`LLM_MODEL` 环境变量。每位成员使用自己的模型配置。本机和内网 IP 的 HTTP 接口可直接在页面保存，无需环境变量预设；HTTP 连接会传输 Key 和请求内容，请使用可信服务。

## LY 功能合入（2026-10-15）

以 LY `05227e0` 的数据源与共享绘图模块实现为基础，保留当前模型配置、GitHub 协作、双击启动和候选检查流程。

- CSV / TSV / JSON + Python 原入口继续保留，并支持嵌套数据目录、显式 `charts/` 与 `lib/`。
- 新增“＋ → 导入 Border / Group Bundle”。支持浏览器上传，或从本机目录复制到项目中。数据与代码默认都保存在项目里，再通过团队协作发布到 GitHub；不要求 NAS。
- 首次导入需指定含 `behavior_analysis/` 的运行时代码目录。此目录只用于复制绘图依赖，原始代码不被改动。Bundle 包含 pickle，需要确认来源可信；导入后绘图直接使用本机 Python。
- Bundle 来源在项目中使用相对路径，可随 GitHub 项目在其他电脑使用。既有 LY 外部路径引用提供兼容接口，但不是默认协作方式。
- 共享绘图模块出现在项目树中，打开后可以手动编辑或让模型提出建议。同一共用函数或同一模块变量的修改默认验证代表图；检测到多个函数或多个模块变量的独立修改时验证全部项目图表，也可主动勾选全量验证。此判断偏保守，不代表自动理解了所有代码语义。
- 验证通过只生成本机候选，展示验证图与影响范围；可以继续修改。勾选已检查并点击应用后才修改正式文件。输入数据或正式模块变化后旧候选会被拒绝。共享模块历史可以取回编辑器，再验证并确认应用。
- Bundle 的渲染结果通过输出观察器衔接已有候选数据与布局检查；不是所有自定义渲染器都可捕获 Matplotlib 对象，无法捕获时明确报错，不报告虚假的数据检查成功。
- Bundle 导出的 SVG/PDF 在原 renderer 只提供 PNG 时仍属于位图封装。已有 CSV/Matplotlib 原生矢量导出保留。

**GitHub 大文件范围**：本轮仍使用普通 Git。浏览器单次上传上限 500 MB；从本机复制不受该上传限制。共享项目总量上限提高到 2 GiB；单文件超过 95 MiB 会阻止发布并列出文件，数据仍保留本机。Git LFS 尚未接入，遇到超限文件需要另行确定 LFS 或数据拆分方案，不会自动改用外部共享目录。

合入前的代码副本保存在本机 `.merge-backups/`，不参与 GitHub 发布。验证包含 LY 单元测试、现有回归、真实 Python 合成 Border/Group 出图与跨目录移动、共享模块候选确认/连续修改/冲突拒绝。尚未使用同事真实的大型实验 Bundle 或在 macOS 真机运行。


## GitHub 项目目录

每个项目统一发布到 `projects/<项目ID>/data/` 与 `projects/<项目ID>/code/`。原始数据和 Bundle 保存在 data；绘图入口在 code/charts，共用模块在 code/lib，项目配置及正式版本记录也归 code。上传时分别选择代码文件夹与数据文件夹，平台会归档到对应项目，不需要手动定位 GitHub 目录。

旧版 charts/lib/project.json 结构仍兼容拉取，下次经平台提交时统一转换为 data/code；原始 Bundle 字节保持不变。新旧位置出现不同内容时会停止并提示，避免覆盖。渲染器内部保留兼容路径，已有绘图脚本与候选不因共享目录整理而失效。

如要自行上传 main，可运行 `python export_shared_projects.py`，生成 `dist/github-projects/projects`，将这一份 projects 放入 GitHub。导出不连接或推送 GitHub，不包含私有候选、配置或密钥；输出目录已有文件时会停止，以免覆盖。桌面 App 也支持从新目录结构的仓库生成安装包。
